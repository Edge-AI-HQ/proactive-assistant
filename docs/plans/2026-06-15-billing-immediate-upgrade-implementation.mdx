# Phase 1 实施计划:升级即时生效

> **For agentic workers:** 逐任务 TDD 执行。每个 Task 内 `- [ ]` 步骤顺序做完再下一个。每个 Task 末尾 commit。

**Goal:** 让套餐升级当期即时生效——当场收取「新档价 − 旧档价」的全差价,确认到账后立即切换 Stripe 价格(不按天 proration)、立即提升 `plan_code` 与 LiteLLM 预算(保留已用 spend);降级保持期末生效不变。

**Tech Stack:** Python / FastAPI / Stripe Python SDK / LiteLLM REST / pytest(异步用 `@pytest.mark.asyncio`,Stripe 与 DB 全 mock,模式见 `tests/web/payment/test_webhook_helpers.py`)。

- [ ] **Step 3: 实现 helper**

在 `checkout.py` 的 `create_or_change_subscription` 函数**之后**新增(`_apply_immediate_upgrade` 用到的 `requires_stripe` / `service_tx` / `subs_repo` / `sync_litellm_budget_for_plan` / `get_subscription_item_id` / `_get_user_stripe_customer_id` / `_stripe_attr` / `HTTPException` / `User` / `logger` 均已在本文件 import):

```python
async def _apply_immediate_upgrade(
    pool,
    *,
    user: User,
    existing_sub: Any,
    current_plan: Any,
    target_plan: Any,
) -> dict[str, Any]:
    """Immediate upgrade: charge the flat (new − old) price difference now,
    and ONLY after it clears swap the Stripe price + promote plan_code +
    raise the LiteLLM budget (spend preserved).

    Flat difference, not Stripe day-proration: our unit of value is credits
    (a quota), not days of access. Upgrading buys the bigger bucket, so the
    charge is the full price delta and the user immediately gets the full
    new allowance. Renewal date is unchanged; next renewal bills full new
    price via the swapped subscription item.
    """
    stripe = requires_stripe()
    customer_id = existing_sub.stripe_customer_id or await _get_user_stripe_customer_id(
        pool, user.id
    )
    if not customer_id:
        raise HTTPException(400, "no Stripe customer for upgrade")

    delta_cents = target_plan.price_cents_monthly - current_plan.price_cents_monthly
    if delta_cents <= 0:
        # Defensive: create_or_change_subscription only routes true upgrades here.
        raise HTTPException(400, "upgrade difference must be positive")

    meta = {
        "kind": "upgrade_delta",
        "supabase_user_id": user.supabase_user_id,
        "from_plan": current_plan.plan_code,
        "to_plan": target_plan.plan_code,
    }

    # 1. Charge the difference NOW and confirm it's paid BEFORE touching any
    #    subscription / plan / budget state. (Sequence verified against Stripe
    #    test mode 2026-06-16 — see "Stripe 验证修正" below.)
    invoice = stripe.Invoice.create(
        customer=customer_id,
        collection_method="charge_automatically",
        auto_advance=False,
        metadata=meta,
    )
    stripe.InvoiceItem.create(
        customer=customer_id,
        invoice=invoice.id,  # attach explicitly, else Invoice totals $0
        amount=delta_cents,
        currency="usd",
        description=(
            f"Upgrade {current_plan.plan_code} → {target_plan.plan_code} (difference)"
        ),
        metadata=meta,
    )
    invoice = stripe.Invoice.finalize_invoice(invoice.id)
    if _stripe_attr(invoice, "status") != "paid":  # skip pay() if already settled
        try:
            invoice = stripe.Invoice.pay(invoice.id)
        except Exception as e:
            try:
                stripe.Invoice.void_invoice(invoice.id)
            except Exception:
                logger.warning("failed to void unpaid upgrade invoice %s", invoice.id)
            raise HTTPException(
                status_code=402,
                detail=f"upgrade payment failed: {type(e).__name__}",
            ) from e
    if _stripe_attr(invoice, "status") != "paid":
        stripe.Invoice.void_invoice(invoice.id)
        raise HTTPException(402, "upgrade payment not completed")

    # 2. Difference paid → swap the recurring price (no day-proration; next
    #    renewal bills full new price) and revoke any scheduled switch.
    item_id = get_subscription_item_id(existing_sub.stripe_subscription_id)
    modified = stripe.Subscription.modify(
        existing_sub.stripe_subscription_id,
        items=[{"id": item_id, "price": target_plan.stripe_price_id}],
        proration_behavior="none",
        billing_cycle_anchor="unchanged",
        cancel_at_period_end=False,
        metadata={
            "supabase_user_id": user.supabase_user_id,
            "plan_code": target_plan.plan_code,
            "pending_plan_code": "",
        },
    )

    # 3. Promote plan_code immediately + raise LiteLLM budget, keeping spend.
    async with service_tx(pool) as conn:
        await subs_repo.sync_from_stripe_subscription(
            conn,
            user_id=user.id,
            plan_code=target_plan.plan_code,
            stripe_subscription=modified,
            update_plan_code=True,
        )
        await subs_repo.clear_pending_plan_code(conn, user.id)
        await sync_litellm_budget_for_plan(
            conn,
            user.id,
            target_plan.plan_code,
            reset_spend=False,
        )

    logger.info(
        "immediate upgrade applied: user=%d %s → %s (charged %d cents)",
        user.id,
        current_plan.plan_code,
        target_plan.plan_code,
        delta_cents,
    )
    return {
        "checkoutUrl": None,
        "flow": "upgrade",
        "applied": True,
        "pendingPlanCode": None,
    }
```

## Stripe 验证修正(2026-06-16,test mode 真跑)

Task 5 提前用 Stripe test mode 复刻了一次升级调用序列(建一次性测试客户+订阅、跑序列、删掉),**抓到两个 mock 验不出的真 bug,已修**:

1. **`InvoiceItem` 必须 `invoice=<id>` 显式挂到 invoice 上**。`Invoice.create` 默认**不**卷入 customer-pending 的 InvoiceItem → invoice total 变 $0、升级白送。修法:先 `Invoice.create`,再 `InvoiceItem.create(invoice=inv.id, ...)`。
2. **finalize 后先查状态,paid 就别再 `pay()`**。`finalize_invoice` 会自动 settle($0 invoice 直接 paid),此时再 `pay()` 抛 `"Invoice is already paid"`,旧代码 `except` 把它当付款失败、错退 402。修法:`if status != "paid": pay()`。
