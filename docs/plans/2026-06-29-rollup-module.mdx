# 统一 Rollup 模块:把 doc §四 的 rollup stage 真正落成模块

> [Lifelong-memory 系统 §四](./2026-06-23-lifelong-memory-system) 把投影管线设计成
> `raw → [rollup 三档] → projector → event`,rollup 是统一的可选 stage(off/window/
> semantic)。但现状**没有 rollup 模块**:声明散在 `event_projector._ROLLUP_MAP`,
> `off` 走 projector 1→1,`window` 没实现(仍 1→1),`semantic` **寄生在 `evolve.py` 的
> prompt job 3**。本 spec 把 rollup 落成真正的模块,并把 semantic 从 evolve 拆出来。

## 一、为什么(现状偏离 doc 设计)

doc §四 的管线图明确 rollup 是**投影管线**(L0→L1)的统一 stage;doc §八 明确 evolve 是
**画像蒸馏**(L1→L2)。但实现把两者混了:

| doc 设计 | 现状实现 | 问题 |
|---|---|---|
| rollup 是统一 stage,三档 | 无 rollup 模块,声明散在 projector | 没有"模块",`projector→rollup→events` 这条线不存在 |
| `off` = 1→1 | projector 直接投 | OK |
| `window` = 规则聚合 | **未实现**,仍 1→1(projector 注释自认)| device snapshot 1→1;且 contacts/apps 被错投成 `interaction`(`_EVENT_TYPE_MAP` 无映射→默认)|
| `semantic` = LLM 卷 firehose→episode(L0→L1)| **evolve.py prompt 的 job 3**(daily sweep 顺手 ROLL UP)| 职责越界:evolve(L1→L2 蒸馏)兼职了 L0→L1 的投影卷,两个 LLM 用途混在一个 agent |

**核心病灶**:semantic rollup(firehose→episode,属投影管线 L0→L1)被塞进 evolve(属画像
蒸馏 L1→L2)。按 doc 自己的分层,它该独立。

## 二、目标终态

`projector → rollup(选档)→ events`,rollup 是**一处声明 + 按进程分实现**的统一 stage:

```
                  ┌─ off     (1→1,projector 直投)         ── api 同步
raw(L0) ─►rollup──┼─ window  (规则聚合,api 侧 rollup)       ── api 同步
                  └─ semantic(LLM 卷 firehose→episode)     ── agent-engine 异步(从 evolve 拆出)
                                                              │
                                              evolve 只剩 L1→L2 画像蒸馏
```

## 三、关键约束:rollup 跨进程(trust boundary)

doc §四 写死「投影管线**临界路径零 LLM**」。所以三档按 LLM/临界性天然分两处实现,**逻辑统一、
物理分居**:

| 档 | LLM | 临界性 | 实现进程 |
|---|---|---|---|
| off / window | ❌ | 同步,raw 落库即投 | **api**(projector 旁)|
| semantic | ✅ | 异步 background | **agent-engine**(从 evolve 拆出的独立逻辑)|

「统一 rollup 模块」= **统一的声明真源(一处说清每 source 走哪档)+ 两处实现**。这不是妥协,
是 trust boundary + 临界路径零 LLM 两条硬约束的必然。

## 四、设计

### 4.1 声明真源:`rollup_policy`(单一处,跨进程可读)

把 `event_projector._ROLLUP_MAP` 提成独立声明,放 **`libs/contracts`**(api + agent-engine
都纯数据读,不互相 import):

```python
# pinai_contracts/rollup_policy.py
ROLLUP_OFF, ROLLUP_WINDOW, ROLLUP_SEMANTIC = "off", "window", "semantic"

# (source, entity/kind) → 档。缺省 off。doc 红线:就这三档,别造可配置 DSL。
ROLLUP_POLICY: dict[tuple[str, str], str] = {
    ("device", "utterance"):          ROLLUP_SEMANTIC,
    ("device", "transcript_window"):  ROLLUP_SEMANTIC,
    ("device", "health"):             ROLLUP_WINDOW,
    # apps / contacts:删掉 window 标记 → 默认 off,但见 4.2(其实该 skip 不投)
}

def rollup_mode(source: str, entity: str) -> str:
    return ROLLUP_POLICY.get((source, entity), ROLLUP_OFF)
```

projector(api)和 rollup-semantic(agent-engine)都 import 这一处,声明不再漂移。

### 4.2 off / window(api 同步,projector 旁的 rollup)

api 侧新建 `domains/user_model/rollup.py`(projector 的伙伴),`project_unprojected` 改成:

```
for raw in unprojected:
    mode = rollup_mode(raw.source, raw.entity)
    if mode == semantic:  continue          # skip,交给 agent-engine(见 4.3)
    if mode == off:       events.append(raw_to_event_input(raw))   # 1→1,现状
    if mode == window:    rollup.window_collect(raw)               # 攒着,见下
window_flush()  # 把攒的按 (local_date × metric) 聚成 1 event/天/metric
```

- **window 真正只服务 `health`**:按 `(local_date, metric)` 把当天同 metric 的 observation
  聚成 1 个 `movement`/`health` event(`structured` 带 min/max/sum/last + count,`source_ref`
  指回当天 raw id 区间)。窗口参数就一个(doc 红线:window 一个参数)。
- **contacts / apps 不走 window,直接不投**:它们是**状态/参考**不是事件(通讯录、装机列表)。
  从 `ROLLUP_POLICY` 删除 → projector 加一个 `_SKIP_PROJECTION` 集合明确跳过(留 L0
  `pai_raw_device` 供 `raw.list` 查)。**顺带修掉它们被错投成 `interaction` 的 bug**。
  > 前置:`grep` 确认没有消费方真的在读 apps/contacts 的 `interaction` event(generation /
  > events_search)。若有,改成查 raw。

### 4.3 semantic(agent-engine 异步,从 evolve 拆出)

现状:semantic rollup 是 `evolve.py` 系统 prompt 的 **job 3**("DAILY sweep 时 ROLL UP
firehose")。拆法:

1. **从 evolve prompt 删掉 job 3** + `_TRIGGER_CONTEXT[DAILY]` 里的 ROLL UP 段。evolve 回归
   纯 L1→L2(curate uncurated queue + distil 画像)。
2. **新建 `agents/rollup_semantic.py`**(agent-engine):一个**专职**的 daily 逻辑,不是通用
   agent loop——
   - 读 firehose:`raw.list("device","utterance",hours=24)` + `transcript_window`(走 SDK,
     Block4 后路由到 `pai_raw_device WHERE kind=...`,已验证)。
   - 一次 LLM 调用(固定 prompt,doc 红线:semantic prompt 固定),按"连续同主题"判边界 +
     摘要,35 句 → 1 episode。
   - 写回:`events.append(event_type="utterance", source="device", source_ref=<区间>,
     dedupe_key=f"episode:device:{cluster_start_iso}")`(幂等,现状契约)。
3. **调度**:daily 触发时,**先跑 rollup_semantic(L0→L1 firehose→episode)、再跑 evolve
   (L1→L2,此时 episode 已在 L1 能被蒸馏)**。两者解耦成两个 background step,不再一个 prompt
   里塞两件事。

> 拆出的收益:① evolve prompt 变短、职责单一(curate+distil),少一个 DAILY-only 分支;
> ② semantic rollup 有独立 prompt + 独立可测(给定 firehose → 期望 episode),不被 evolve 的
> curate 逻辑干扰;③ 对齐 doc 分层(投影管线 vs 画像蒸馏)。

### 4.4 projector ↔ rollup 接法

projector 现有 3 个同步调用点(`connector_ingest` ×2 + `devices_ui` ×1)不变,内部
`project_unprojected` 按 4.2 改成"查 rollup_mode 分派"。semantic 源在这里 `continue`(skip),
不进 L1;agent-engine 的 rollup_semantic 异步补上。和现状 `_SEMANTIC_SKIP_ENTITIES` 的行为
一致,只是换成读 `rollup_policy` 统一声明。

## 五、Work Packages

| WP | 内容 | 进程 | 依赖 |
|---|---|---|---|
| **R1** | `pinai_contracts/rollup_policy.py`(声明真源 + `rollup_mode`),projector 改读它(替 `_ROLLUP_MAP`/`_SEMANTIC_SKIP`)。行为不变,纯收口声明 | contracts + api | — |
| **R2** | contacts/apps:从 policy 删 + projector 加 `_SKIP_PROJECTION`;修错投 `interaction` bug(先核实无消费方)| api | R1 |
| **R3** | `domains/user_model/rollup.py` + window 实现(health 按天×metric 聚合);projector 接 window 分派 | api | R1 |
| **R4** | `agents/rollup_semantic.py`(从 evolve 拆 job 3:独立 prompt + daily step)| agent-engine | R1 |
| **R5** | evolve 瘦身:删 prompt job 3 + DAILY ROLL UP 段;daily 调度改「先 rollup_semantic 后 evolve」| agent-engine + 调度 | R4 |

> R1/R2 是低风险收口(声明统一 + 修 bug),可先落。R3 是 window 真正实现(只 health)。
> R4/R5 是 semantic 从 evolve 拆出,改动 evolve prompt + daily 调度,风险最高、最后做 + 配端到端验。

## 六、风险

- **R4/R5 改 evolve prompt + daily 调度**:semantic rollup 拆出后,daily 顺序错(evolve 先跑、
  episode 还没卷出来)= 当天 firehose 不进画像。R5 必须保证 rollup_semantic 在 evolve 前。
- **window health 聚合的语义**:min/max/sum 哪些有意义因 metric 而异(步数 sum、心率 avg/max),
  聚合函数可能要 per-metric。先做最简(count + last + sum),按需扩。
- **contacts/apps 改 skip**:若真有消费方读它们的 event(R2 前置核实),要同步改成查 raw。
- **semantic 端到端质量**:拆出后 episode 质量(分段对不对、不过度切)仍需真实 ambient 数据验
  (本地验不出,见母 plan §十三 未竟项)。
