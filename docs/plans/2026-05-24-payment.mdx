# 支付模块 MVP:订阅 + LiteLLM 预算同步

## 结论

PIN AI 走**纯订阅模型**(对标 ChatGPT / Claude.ai),3 档 basic $39 / pro $99 / max $199,每档每月对应 N credits(`monthly_refresh_credits`),credits 翻译成 LiteLLM `max_budget` USD 上限(100 credits = $1)。7 天免费试用,Stripe Checkout 跳转付款。

后端骨架(`backend/src/pinai_agents/web/payment/` ~910 行 + 027 三张表)已存在。本 plan 补齐 4 块缺失:**升降级 / 取消 / LiteLLM 同步 / 前端接线**。**不上 Stripe Meters** ── B2C 聊天助手行业不走按量,等 6 个月后再评估加超量档。

## 总目标

用户能在 dev 完整跑通:

1. 前端选档 → Stripe Checkout 跳转 → test card `4242 4242 4242 4242` 付款 → 跳回成功页
2. 7 天免费试用,第 8 天 Stripe 自动扣月费
3. 升级(basic→pro)立扣差价 + 立刻生效;降级(pro→basic)下期生效
4. 取消:`cancel_at_period_end`,本期继续用,下期不续
5. `invoice.paid` webhook → LiteLLM `max_budget` 设到该档 USD,`spend` 重置
6. 前端能显示当前订阅状态 + 进 Stripe Customer Portal 自服务管理

## 不变约束(循环任何时候都不能违反)

1. **trust boundary**: `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` 只在 web 进程,chat 进程禁止读取(由 `chat/trust_boundary.py` 的 `FORBIDDEN_ENVS` 保护)。
2. **migration 不可改**: 一旦 merge 到 main 不再修改。本 plan 新增 057,不动 027 已 merge 的 schema(027 字段不删不改,只 `ALTER TABLE … ADD COLUMN`)。
3. **Stripe price 不可改 amount**: Stripe 强制不变,改价 = archive 旧 + 建新(2026-05-24 已 done)。
4. **`invoice.paid` 是唯一触发 LiteLLM reset 的事件**: 其他 webhook 事件不动 LiteLLM 状态。`invoice.payment_succeeded` 显式 skip(SSOT 是 `invoice.paid`)。
5. **webhook idempotency**: 所有 webhook 处理用 `pai_stripe_webhook_events.event_id` UNIQUE 去重(现有 `webhook.py` 第 46-63 行已实现,不动)。
6. **user_id 外部标识**: Stripe metadata / Customer description / LiteLLM user_id 一律用 `users.supabase_user_id`(UUID,跨环境一致),禁止用内部 BIGINT `users.id`(AGENTS.md L289 硬规)。
7. **不主动退款**: 用 `cancel_at_period_end` 软取消, 与 PIN Claw 一致。
8. **iOS 平台 = 方案 A**: App 只显示状态,要付钱跳 Web;不接 Apple IAP / StoreKit;Apple External Link Account Entitlement 在 App Store 提审时申请。
9. **遵守仓库编码原则**: 无 `as any` / `# type: ignore` / `eslint-disable`(除非注释说明唯一选项);改动最小化;复用同模块已有 pattern。

**checkout.py 三分支伪代码**:

```python
async def create_or_change_subscription(
    user: User, target_plan: Plan, conn: Connection,
) -> tuple[str | None, dict]:
    """
    Returns (checkoutUrl, info). checkoutUrl is None when the change is
    applied directly via subscription.modify (upgrade / downgrade).
    """
    existing = await find_active_subscription(conn, user.id)
    customer_id = await ensure_stripe_customer(user, conn)

    if not existing:
        # NEW: trial-bearing checkout
        session = stripe.checkout.Session.create(
            mode="subscription",
            customer=customer_id,
            line_items=[{"price": target_plan.stripe_price_id, "quantity": 1}],
            subscription_data={
                "trial_period_days": target_plan.trial_period_days,
                "metadata": {
                    "supabase_user_id": user.supabase_user_id,
                    "plan_code": target_plan.plan_code,
                },
            },
            success_url=f"{settings.payment_public_base_url}/account?checkout=success",
            cancel_url=f"{settings.payment_public_base_url}/account?checkout=cancel",
            allow_promotion_codes=True,
        )
        return session.url, {"flow": "new"}

    if existing.plan_code == target_plan.plan_code:
        raise HTTPException(400, "already on this plan")

    item_id = await get_subscription_item_id(existing.stripe_subscription_id)
    target_price_cents = target_plan.price_cents_monthly
    existing_price_cents = (await plans_repo.find_by_code(conn, existing.plan_code)).price_cents_monthly

    if target_price_cents > existing_price_cents:
        # UPGRADE: prorate + invoice immediately, take effect now
        stripe.Subscription.modify(
            existing.stripe_subscription_id,
            items=[{"id": item_id, "price": target_plan.stripe_price_id}],
            proration_behavior="always_invoice",
        )
        return None, {"flow": "upgrade"}

    # DOWNGRADE: no proration, hold this period's higher budget, switch next cycle
    stripe.Subscription.modify(
        existing.stripe_subscription_id,
        items=[{"id": item_id, "price": target_plan.stripe_price_id}],
        proration_behavior="none",
        billing_cycle_anchor="unchanged",
    )
    return None, {"flow": "downgrade"}
```

**cancel + customer-portal endpoint 骨架**:

```python
@router.post("/cancel")
async def cancel(user=Depends(supabase_user), conn=Depends(db_conn)) -> dict:
    sub = await subs_repo.get(conn, user.id)
    if not sub or not sub.stripe_subscription_id:
        raise HTTPException(400, "no active subscription")
    stripe.Subscription.modify(sub.stripe_subscription_id, cancel_at_period_end=True)
    return {"ok": True}

@router.post("/customer-portal")
async def customer_portal(user=Depends(supabase_user), conn=Depends(db_conn)) -> dict:
    sub = await subs_repo.get(conn, user.id)
    if not sub or not sub.stripe_customer_id:
        raise HTTPException(400, "no Stripe customer")
    portal = stripe.billing_portal.Session.create(
        customer=sub.stripe_customer_id,
        return_url=f"{settings.payment_public_base_url}/account",
    )
    return {"portalUrl": portal.url}
```

## Goal 3 — LiteLLM 预算同步(依赖 Goal 1)

**目标**: `invoice.paid` 真正落 LiteLLM;`subscription.deleted` 真正清零。

**交付物**: `web/payment/webhook.py` 的 `_handle_invoice_paid` + `_handle_subscription_deleted` 补完。

```python
# web/payment/webhook.py
from ..litellm.client import litellm_client  # existing

_CREDITS_PER_USD = 100  # 100 credits = $1 USD,与 PIN Claw / 当前 monthly_refresh_credits 一致

async def _handle_invoice_paid(conn, invoice: Any) -> None:
    """invoice.paid is the SSOT for renewing LiteLLM budget. Other
    invoice.* events are skipped on purpose."""
    sub_id = invoice.get("subscription")
    if not sub_id:
        return
    user = await find_user_by_subscription(conn, sub_id)
    if not user:
        logger.warning("invoice.paid without resolvable user (invoice=%s)", invoice.get("id"))
        return
    plan = await plans_repo.find_by_code(conn, user.plan_code)
    if not plan or not user.litellm_virtual_key:
        return
    budget_usd = plan.monthly_refresh_credits / _CREDITS_PER_USD
    await litellm_client.update_key(
        user.litellm_virtual_key,
        max_budget=budget_usd,
        budget_duration="30d",
    )
    await litellm_client.reset_key_spend(user.litellm_virtual_key)

async def _handle_subscription_deleted(conn, sub: Any) -> None:
    user = await find_user_by_subscription(conn, sub.get("id"))
    if user and user.litellm_virtual_key:
        await litellm_client.update_key(user.litellm_virtual_key, max_budget=0)
```

**注意**: `litellm_client.update_key` / `reset_key_spend` 的具体函数名以 `web/litellm/client.py` 现有 API 为准,实施时如名字不同按现有 API 命名。如果没有 `reset_key_spend`,等价做法:把 `max_budget` 先设到 0 再设到目标值(LiteLLM 文档支持此方式)。

- **自实现 billing history 页面**(用 Stripe Customer Portal,1 行代码接入)

- **refund endpoint**(跟 PIN Claw 一致,不主动退款,用户自己走 Stripe / 客服)
