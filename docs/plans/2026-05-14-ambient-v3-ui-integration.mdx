# Ambient V3 UI 接入 Phase 1 Implementation Plan

> **For agentic workers:** 本 plan 记录 `proactive-ai-frontend` Constellation UI 端把 ambient runtime 接通的 5 个 commit（`feat/ambient-v3` 分支）。改 `src/components/constellation/AmbientView.tsx`、`ControlPanel.tsx`、`services/ambient/*` 之前必读；Phase 2 卡片合成开工前也回查这里的决策。

## 结论

- **Phase 1 已上线** `feat/ambient-v3` 分支（5 commits，对 `proactive-ai-frontend` 6 文件 +471 / -49）：顶层 Ambient 开关、全局上传锁、Live 卡片真转录、Control Panel Models tab、web bundle native specifier 修复。22 个 ambient 测试 + 全量 typecheck 全绿。
- **核心决策（用户拍板）**：
  - 顶层 Ambient 开关 = 控制全部 5 个 source（sensor-fusion / health / notification-usage / media-notebook / nearby）。**不**在 UI 上暴露 per-source 开关（除了 dev-only Debug Panel）。
  - Global Lock = **软锁**，对齐老 iOS Ambient Plugin 行为：本地继续 capture / write outbox，仅暂停上传 drain。Unlock 后自动 resume。
  - Live 卡片消费真实 `AmbientAi.transcriptReady` event，按 `captureSessionId` 分桶；**Timeline 仍是 mock**（Phase 1 不接 server 卡片流）。
  - Models tab 嵌在 `ControlPanel`，**native-only**，web 上 `isNative===false` 直接给文案提示，不渲染下载 UI。
  - 权限**串行请求**：用户开 Ambient 后依次走 `requestPermissions()`，单 source 拒了就跳过，不阻塞其它 source。
  - Card synthesis（用 on-device LLM 把 transcript chunk 合成主动卡片）**Phase 2 再做**，本期不开工。
- **Web build 强约束**（已踩坑修过一次，必读）：任何会触碰 `@pin/capacitor-ambient-ai` / `@capacitor/geolocation` 等 native plugin 的代码**必须**走动态 `import()` + `isNative` 短路；UI 组件用 `React.lazy`。常量 / 类型抽到 side-effect free 的 `services/ambient/keys.ts`。本期 commit `69d520c0` 修过一次同款问题，犯第二次会让 web `/` 直接白屏。
- **Phase 2 待办**：on-device LLM 卡片合成；`ConstellationLayout` 首屏 `LIVE_SCENARIOS[0]` overlay 接真 session；health source autoStart 策略讨论；Models 下载进度 UI 跟 Constellation 视觉对齐。

## Phase 1 落点（按 commit 拆）

### 1. `0eb43d38` — soft upload lock at scheduler 层

**Why**：对齐老 iOS Ambient Plugin 的 Global Lock 行为（本地继续采集、只锁上传），别让 Unlock 时丢历史 capture。

- `services/ambient/sync-scheduler.ts`：新增 `uploadsLocked: boolean` 状态、`setUploadsLocked(v)` setter、`isUploadsLocked()` getter；`drain()` 在 `uploadsLocked === true` 时短路返回，不消 outbox。
- `services/ambient/index.ts`：runtime 暴露 `setUploadsLocked()` 方法 + `uploadsLocked` 字段进 `RuntimeStatus`；状态 localStorage 持久化（key: `ambient.uploadsLocked`），刷新页面不会"自动 unlock"。
- `services/ambient/sync-scheduler.test.ts`：新增 2 个 vitest case —— "locked 时 drain 短路" + "unlock 后 drain 恢复消费 outbox"。

### 2. `bb732cc0` — Ambient hero 接 settings / runtime + Lock 按钮

**Why**：让 v3 Ambient 视图顶部的"On / Off"和"Lock"按钮不再是 mock，直接驱动真 runtime + user settings。

- `components/constellation/AmbientView.tsx`：
  - 顶部 hero 删掉本地 `useState`，改读 `useUserSettings()`，开关 = `patch({ ambientSources: { [key]: { enabled } } })` 对 5 个 source 一次性写。
  - 订阅 runtime status，渲染当前已 running source、错误、Lock 状态。
  - 新增"Lock uploads / Unlock"按钮，调 `runtime.setUploadsLocked()`；按钮 disabled 状态跟 `RuntimeStatus.uploadsLocked` 同步。
  - 启动顺序：**串行 `requestPermissions()` → 用户拒了跳过 → 调 `runtime.startSource(key)`**。
- `services/ambient/index.ts`：导出 `ALL_SOURCE_KEYS`（后被 `69d520c0` 挪到 `keys.ts`）。

### 3. `c21f635e` — Live 卡片消费真 `transcriptReady`

**Why**：让 Constellation Ambient 视图的 Live card 不再 hardcode，转而展示当前 ambient session 的真实转录。

- `components/constellation/AmbientView.tsx`：
  - 新增 `LiveSessionData` / `appendTranscript` 内部 helper，按 `captureSessionId` 分桶累加 transcript chunk。
  - 通过动态 `import('@pin/capacitor-ambient-ai')` → `AmbientAi.addListener('transcriptReady', ...)` 订阅事件；unmount 时清理 listener。
  - 真转录数据**覆盖** mock；订阅前 / 无 session 时显示 mock fallback（保证 web preview 视觉不空）。
  - **Timeline 仍走 mock**：本期不接 server card 流，Phase 2 再做。

### 4. `5b283164` — Control Panel Models tab

**Why**：on-device ASR + LLM 模型下载入口要进 v3 产品壳，而不是只在 dev Debug Panel。

- `components/constellation/ControlPanel.tsx`：新增 "Models" tab，嵌 `AmbientModelsPanel`（来自 V2 平移的现成组件），外层套 Constellation 卡片 chrome。
- `isNative === false`（web）直接渲染文案"Open in the iOS app to manage on-device models"，**不**尝试拉模型清单。
- 9 个模型 profile（ASR ggml + LLM GGUF）走 plugin manifest，下载源 hf-mirror → hf fallback。

### 5. `69d520c0` — fix: web bundle 不夹 native bare specifier

**Why（生产 bug）**：前面 4 个 commit 把 `@pin/capacitor-ambient-ai` 等 native 包名直接 import 进了主路由 chunk。`vite.config.ts` 把这些标了 `rollupOptions.external`，结果 web build 的主 chunk 里残留裸 `from"@pin/capacitor-ambient-ai"`，浏览器加载报 unresolved specifier → `/` 白屏。

- `services/ambient/keys.ts`（新增，**side-effect free**）：导出 `SourceKey` 类型、`ALL_SOURCE_KEYS` 常量、`DEFAULT_AUTO_START_SOURCES`。
- `components/constellation/AmbientView.tsx`：
  - `services/ambient/index`、`@pin/capacitor-ambient-ai` 等全部改成 `await import()`，并外层 `if (!isNative) return` 短路。
  - 类型 / 常量从新 `keys.ts` 拿，不再触发 runtime 模块加载。
- `components/constellation/ControlPanel.tsx`：`AmbientModelsPanel` 改 `React.lazy(() => import(...))` + `<Suspense>`，且 `isNative === false` 时不挂载。
- `services/ambient/index.ts`：re-export `keys.ts` 内容，保持上游导入路径兼容。

**验证**：本地 `npm run build` + `docker compose build frontend`，主 chunk grep 不到 `@pin/capacitor-ambient-ai` / `@capacitor/geolocation`，全部落到懒加载 chunk（`index-C92QaCX5.js` 等）。Playwright 跑 `/` 跟 `/?preview=1`，前者出 LoginPage，后者出 Constellation 主壳 + Ambient row + Live mock，0 pageerror。

## 已知约束 / Pitfall

### 1. Web 主 chunk 不能含 native bare specifier

- `vite.config.ts` 把 `@pin/capacitor-ambient-ai` / `@capacitor/geolocation` 等标了 `rollupOptions.external`。
- 主路由 chunk 一旦含 `from"@pin/capacitor-ambient-ai"` 等裸 import，浏览器拒绝加载 → `/` 整页白屏。
- **规范**：
  - UI 组件用 `React.lazy()` 包；
  - 业务调用走 `await import('@pin/capacitor-ambient-ai')`；
  - 外层用 `isNative` guard，且这个 guard 要在**模块顶层 statement** 之外（如 in-handler），否则 tree-shake 可能 keep dead branch。
  - 常量 / 类型用 `services/ambient/keys.ts`，不要从 `services/ambient/index.ts` re-export 静态拿。

### 2. `VITE_*` env 必须 build-time 注入

- `services/auth/supabase.ts` 在模块顶层读 `import.meta.env.VITE_SUPABASE_URL` 并抛 `throw`。
- 本地直接 `docker compose build frontend` 会跳过 `make build` 里的 `export_vite` step → image 启动时整页白屏 + 控制台 `Missing VITE_SUPABASE_URL...`。
- **规范**：rebuild frontend 走 `make build frontend` 或 `make up`，自动从 `pinai-agents/.env` `set -a` 注入 `VITE_*` 到 build-arg。

### 3. Lock 视觉跟 ambient row 的 status badge 还没对齐

- Lock 按钮在 hero 区，但 ambient row 当前没有可视化 "uploads paused" 标识；用户体验上"开着 Ambient 但锁着上传"的状态略模糊。
- Phase 2 / UI polish 跟 row 视觉对齐时再补。
