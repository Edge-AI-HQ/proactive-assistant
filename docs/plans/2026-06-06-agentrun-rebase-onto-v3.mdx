## 三、策略:为什么是「v3 基线」而非「rebase」

逐 commit rebase 的致命点:你的前端统一 commit(`3196246f` unify into ProactiveAgentView、`8de106d2` rename → Conversation)会和 v3 的 god-component 拆分(#32 那 20 个 commit)在同一批文件上反复爆冲突;ambient 上你「砍薄」(`live-session.ts` -479、`AmbientView.tsx` -635)和 v3「做厚」(+timeline 子系统)方向相反。27 次 replay = 27 次凭记忆重建意图。

**以 v3 为基线 = v3 的一切默认在,你只做加法和对账。** 终态可 `force-update` 回 `feat/agentrun`(设计 plan 的 commit 历史保留在 docs,不丢)。

```bash

```

## 四、关键架构事实(代码验证,方案据此成立)

1. **worker→/agent/chat 链路通** ✓ `agent_core/client.py` 注释「Reuses the existing /agent/chat SSE endpoint」,v3 的 `chat/transport/routes/chat.py:240` **已有** `@router.post("/agent/chat")`。worker(web)自己不碰 sandbox,通过 HTTP 委托 chat 进程。

2. **lazy sandbox 是「白拿」** ✓ 真正 provision sandbox 的是 chat 进程构建 main_chat 处。基线 = v3,`lazy_sandbox.py`(`LazyThreadSandbox(SandboxBackendProtocol)` 代理,首次 `aexecute` 才 provision)和 main_chat 的 lazy 接线默认就在。A 组只需「取 v3 main_chat + 回贴你 2 行」。

3. **你的 HITL 与 v3 lazy 不打架** ✓ 你的 `harness/factory.py` 改动 = 给 `build_agent` 加可选参 **`interrupt_on`**(deepagents `HumanInTheLoopMiddleware`),有默认 `None` → v3 main_chat 不传它照常工作(additive 兼容)。你 main_chat 那 2 行正是 `interrupt_on` **透传**。三文件(factory / main_chat / chat.py)协同让 **lazy(v3)+ HITL(你)共存**。

4. **v3 ambient 已上云,且含逐句 utterance** ✓(纠正讨论中途的误判)`sound-classifier.ts:494` 的 `pushTranscript` 以 `kind: "session_summary"` POST `/api/devices/ingest`,payload 带 `speaker_segments`(逐句+说话人+时间戳)、`self_text`、`speaker_labels`、diarization。**不需要为 utterance 改 v3 客户端加上云**。

5. **后端 ingest 契约稳定** ✓ v3 **未改** `device_ingest/policies.py` 和 `routes/ui/devices.py`(你的 dual-write +176 行 apply 零冲突);v3 改的 77 行 `api_models.py` 全是 `DevelopmentFeedback*` + generator,**没碰** ingest 契约;v3 对 `lib/devices.ts` 只 additive +5。`kinds.ts` 注释金句:「backend routes by kind and does not validate payload shape」。

6. **两套 SSE 协议** ⚠️ 你 `useConversationRuntime` = `/api/conversation/{history,stream,send}` + 统一 envelope + long-lived SSE(send 走 202、reply 异步到 stream);v3 `useProactiveChatRuntime` = `chat:*` 事件 + request-response SSE。B 组接缝是**换协议**,不是换 hook。

7. **migration 改号机械安全** ✓ `080~084` 被 0 个非自身文件引用;`082_agent_core` 只 `REFERENCES users(id)`(基础表),不依赖近期 migration,改号不破依赖。
