# Ambient AI 发布前问题清单（目标日期 2026-06-15）

> 生成日期：2026-06-03
> 分支：`proactive-ai-v3`
> 扫描范围：iOS 音频/VAD 层、iOS 端上 LLM/ASR 模型层、TS timeline pipeline + outbox、TS 采集 + source 适配器、React UI + hooks、后端 ingest + ambient summary
> 工具：6 路并行静态深读 + 关键热点 commit diff（最近 5 个 ambient commit）

---

## 0. 一句话定调

关键链路有静默回归：
1. **Foreground Silero VAD tap 实际从未触发**（commit `5a02430e` 名义上换了，code 里 `start()` 路径少调 `onAudioBuffer`）。
2. **端上 LLM 每个 cycle 都冷加载模型 + Metal 重编译**，180s timeout 在真机经常一个 token 都来不及输出。
3. **端上 LLM 是纯 greedy argmax 无 repetition penalty**，小模型直接 loop。
4. **TS pipeline 没有锁**，auto refresh + manual "Summary now" 会双触发 native LLM。
5. **后端 `ambient_summary.text` `max_length=320`** 跟 Silero v5 放宽后的转录长度对不上，会 422 把整批拒掉——本质是 commit `cdd39d30` 修过的"drop short transcripts"问题从客户端搬到了服务端。

## 2. P0 — 阻塞发布

### 2.1 iOS 音频 / VAD 层

- **[P0-A1] `capacitor-plugins/ambient-ai/ios/Sources/AmbientAi/Audio/AudioStreamManager.swift:177-179`** — Foreground Silero VAD 实际不收音频。`start()` 装的 tap 只调 `dispatchAudioBuffer` + `analyze`，**未调 `onAudioBuffer?(buffer)`** → `SileroVadGate.ingest()` foreground 永远拿不到样本。只有 background-only `startCapturePipelineOnly()`（line 256-260）同时调 `onAudioBuffer`。**直接让 commit `5a02430e` 在 foreground 失效**。

- **[P0-A2] `Audio/AudioStreamManager.swift:298-333`** — 每个 burst 丢头 100–300ms。`handleSpeechBurst` 立刻置 `isCapturing=true`，但 sink 在 `runOneCaptureCycle` await 之后才 attach（line 411）。Tap 在这段间隙里把 leading frames 丢进 preRollBuffer，不进当前 cycle 的 recorder。

- **[P0-A3] `Audio/AudioStreamManager.swift:354-367`** — `backgroundCaptureLoop` generation race。快速前后台切换时 `stopBackgroundCaptureLoop` bump generation，仍在跑的 Task 完成时可能把刚启动的新 loop 给 nil 掉 → 两个 loop 并发跑 `startCaptureCycle`。

- **[P0-A4] `Audio/AudioStreamManager.swift:1374-1395`** — `SpeechRecognitionCoordinator.canAttemptRecognition` 不检查 `activeTask != nil`。第二次 `beginRecognition` 直接覆盖前一个 task；同一段录音 fan-out 出 4–6 个并发 `recognitionTask`，违反 Apple "one active SFSpeechRecognitionTask per recognizer" 限制。

- **[P0-A5] `Audio/SileroVadGate.swift:204-253`** — `AVAudioConverter` 被 audio tap 线程直接 mutate 无同步：
  ```swift
  if converter == nil || converterSourceFormat?.isEqual(inputFormat) != true {
      converter = AVAudioConverter(...)
      converterSourceFormat = inputFormat
  }
  ```
  路由切换（AirPods 插拔）时 inputFormat 变化，tap 线程半写状态可被另一线程观察到。

- **[P0-A6] `Audio/SileroVadGate.swift:256-265`** — `.unbounded` AsyncStream backpressure。CoreML 热降频时 backlog 无上限，无 drop-oldest → OOM。

- **[P0-A7] `Audio/SileroVadGate.swift:139-145`** — Silero 模型 load 失败后 chunk stream 仍开着。Processor task 早 return，但 `ingest` 继续往 `.unbounded` stream 灌样本 → 内存常年攀升。

### 2.2 iOS 端上 LLM / 模型

- **[P0-B1] `capacitor-plugins/ambient-ai/ios/Sources/AmbientAi/Plugins/AmbientModelsPlugin.swift`** — `generateAmbientSummaryEvent` 在 native 端**没注册** `CAPPluginMethod`。JS 侧 `models.ts:368` 的 `if (!api.generateAmbientSummaryEvent)` 拦不住（Capacitor proxy 给 truthy function），运行时 `UNIMPLEMENTED`。`summary-bridges.ts:13` 的 cloud fallback 也会撞上。

- **[P0-B2] `Models/LlamaTextGenerationEngine.swift:191-215`** — `llama_chat_apply_template` **不是 Jinja 解释器**。llama.h:1154 明说 "does not use a jinja parser, only supports a pre-defined list of template"。Gemma 2/3 IT、新版 Qwen3 的 Jinja 大概率不在 llama.cpp 的内置 lookup → probe 返回 -1 → `chatTemplateApplyFailed`。**设计 SSOT §6.2 描述错了**。

- **[P0-B3] `Models/LlamaTextGenerationEngine.swift:312-343`** — 纯 greedy argmax，**无** repetition penalty / top_k / top_p / temperature。Qwen3 0.6B / Gemma 2 2B 在小输入下经常 A → B → A → ... loop 把 maxTokens=512 全填满；JSON shape 仍可能 pass。

- **[P0-B4] `Plugins/AmbientModelsPlugin.swift:189`** — Prefill + text 拼接产生 `{{` 双开括号。`combined = plan.prefill + text`，prefill 是 `{"decisions":[{`，模型若再次输出 `{` 就变成 `{"decisions":[{{...}]}` 无法解析。

- **[P0-B5] `Models/LlamaTextGenerationEngine.swift:265-279`** — Tokenize buffer `utf8Count + 8`，对中文/CJK + chat-template special token 不够。当 `nTokens == maxTokenCount` 时 buffer 边界刚好 fit，但前缀未 memset，position ≥ N 是垃圾。

- **[P0-B6] `Models/LlamaTextGenerationEngine.swift:142-167`** — `mergeSystemIntoFirstUserIfNeeded` 用 `lowercased().contains("system")` 判模板是否接 system role。不接受 system role 的模板也常在 Jinja 注释/宏里出现 "system" 字面量 → Gemma 模板拿不到 merge → `chatTemplateApplyFailed`。

- **[P0-B7] `Plugins/AmbientModelsPlugin.swift:25` + `LlamaTextGenerationEngine.swift`** — 每次 `generateTimelineBatchDecision` 都重新 `llama_model_load_from_file`。真机 1.1GB Qwen3 1.7B + Metal full offload 冷加载 5–15s + 4–10s shader 编译。15 分钟 cadence 每轮付一次，**首跑 180s timeout 几乎必中**。

- **[P0-B8] `LlamaTextGenerationEngine.swift:255-261`** — `n_ctx=4096` + `n_gpu_layers=99` + Gemma 3 4B IT 在 4GB-RAM 设备（XR/SE2/SE3）必 jetsam。无 device-tier 选择（§11 TODO #8 未实现）。

- **[P0-B9] `LlamaTextGenerationEngine.swift:345-356`** — UTF-8 跨 token 边界丢字。每 token 单独 `String(bytes:, encoding:.utf8)`；3 字节中文字符在 token 边界被截成 2 字节时整 piece 被丢 → **中文输出可见地少字**。

- **[P0-B10] `LlamaTextGenerationEngine.swift:174-183`** — `strdup` + `free` 双释放路径。`strdup` 对某个 role 返回 nil 触发 guard 时，guard body 已 `free()` 部分指针，外层 `defer` 再 free → crash。

- **[P0-B11] `Models/ModelDownloader.swift:50-67, 354-372` + `Models/ModelManifest.swift:15`** — `.ggml` magic 字节序错。写的是 `[0x6c, 0x6d, 0x67, 0x67]`（"lmgg"），真正的 ggml magic 是 `0x67676d6c`（"ggml"）。**所有 whisper-base / whisper-small ASR 下载完整失败**。

- **[P0-B12] `Models/ModelDownloader.swift:67-72`** — Background URLSession 没注册 `handleEventsForBackgroundURLSession`。后台完成时 iOS 把 callback 投给 AppDelegate，**没实现** → 后台完成事件丢失。

- **[P0-B13] `Models/ModelDownloader.swift:227-273`** — 无 cert pinning，无 sha256 verify，整模型链路只校验 4 字节 magic。GGUF 历史有过堆解析 CVE 级 bug，下到设备直接 Metal 跑——MITM 攻击面真实存在。

- **[P0-B14] `Models/ModelDownloader.swift:135-158`** — `cancel` 与 finish 竞态留孤儿：cancel 没删 staging 文件，没记 lastStatus 转换；finish 在 cancel 后跑到的话会把 model 偷偷重装回来，状态显示 absent 但磁盘还在。

- **[P0-B15] `Plugins/AmbientModelsPlugin.swift:151-211`** — 同模型 re-entrant generation 无跨 call 锁。两个并发 caller 触发两个 `llama_model_load_from_file` 跑同一 GGUF + 共享 Metal queue → 行为未定义。§11 TODO #2 已知未做。
