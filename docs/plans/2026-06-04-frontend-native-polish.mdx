## 结论(已拍板的前提)

把产品前端 `proactive-ai-frontend` 打磨到 best-in-class。两个已定的决策:

### 1. 平台:留在 Capacitor,不迁 React Native / 原生 SwiftUI

理由:

- **原生集成已经很深**:自研插件 `@pin/capacitor-ambient-ai`(34 个原生 Swift/Kotlin 文件)+ health / barometer / contacts / sqlite / secure-storage / haptics / push… 换平台 = 这些全部重写重测。
- **一套码同时出 iOS + Android + Web**;迁 RN 会切断 Web,迁原生只剩 iOS。
- 刚建好的 **Lovable 设计流水线**依赖 Web 技术(见「相关」)。
- 对「AI 助手」这类**非图形密集** App,新 iPhone 的 WebView 天花板足够撑起高级感 —— 用标准打法补满即可。

> ⚠️ 诚实天花板:WebView 摸不到「绝对 120fps 手势密集」的最后一档;要捅破只有 RN/原生,但对本 App 代价远大于收益。

### 2. 范围:原生质感 + 视觉设计都要,分阶段推进

排序逻辑:**先打地基(后面全靠它)→ 修最常被感知的交互 → 补细节 → 抠性能 → 沉淀组件 → 打磨招牌**。每个阶段都能独立上线 + 在 iPhone 真机验收。
