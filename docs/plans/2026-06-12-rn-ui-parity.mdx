## 2026-06-12 晚调研修正（用户拍板）

四路调研（业界路线 / 顶级 app 栈 / RN 视觉硬技术 / 本仓库差距审计）结论：**架构方向不动**（core/state 共享 + RN UI 独立 = 2026 业界正解，不引入 Tamagui/RNW/react-strict-dom），「效果差」根因 = **渲染介质错配**——NativeWind 只对齐 token/类名语法，对齐不了渲染能力（RN 无 backdrop-filter、iOS filter 只有 brightness/opacity）。修正三条：

1. **介质映射替代 className 直译**（视觉表现层不走类名翻译）：

   | Web 介质 | RN 正确介质 |
   |---|---|
   | `backdrop-filter: blur+saturate` 玻璃 | expo-blur（iOS UIVisualEffectView，light/material tint 自带 saturate 增益）+ RN 0.76+ `boxShadow`（含 inset 高光） |
   | aurora 多层 radial 斑 + blur(60) + mix-blend screen | Skia 静态画斑（带 Blur）+ Reanimated transform 漂移 + RN 0.77+ `mixBlendMode:'screen'`；`bg-gradient.jpg` 资产搬运 |
   | `bg-clip-text` 渐变文字 / shimmer | `@react-native-masked-view/masked-view` + LinearGradient |
   | framer-motion 动效 | **弃 moti（停滞 15 个月，实际零使用，删依赖）**→ Reanimated 4（spring 与 framer 同物理模型、参数同名可直搬） |
   | 流式 markdown | block-memo 策略（完成块永不重渲）；react-native-streamdown 太年轻先观察 |
   | 真 3D（r3f） | 不用（expo-gl 错配 + New Arch issue）；球面云保留手算投影 + z 排序 |

2. **验收从凭感觉改为截图对照**：XcodeBuildMCP 模拟器截图 vs web 基准并排对照；后续建 Maestro `assertScreenshot` 基线。web↔RN 直接像素 diff 不可行（渲染器差异），用并排拼图人审。
3. **目标校准**：100% 像素一致不可达也不必要，目标 =「度量一致（token/字距/动效参数）+ 介质等效（blur/渐变/物理）」；个别点（iOS 26 Liquid Glass）允许比 web 更好。Android blur 贵，准备实色降级皮肤（web 已有 `native-power-save` 同构先例）。

## 已拍板决策（2026-06-12，用户确认）

1. **复用机制 = NativeWind 4 + 共享 tailwind 设计 token + lucide-react-native（图标同名）**。~~+ moti~~（调研后弃用，动效改 Reanimated 4——见上修正）。组件本体无法跨平台 import（RN 无 DOM/CSS 引擎——这是 Electron 能 100% 复用而 RN 不能的本质），布局/排版类 className 照抄成立；**视觉表现层（玻璃/渐变/阴影/动效）走介质映射表，不走 className 直译**。
2. **导航完全照 web**：删 bottom tab；右上 齿轮+汉堡 双圆钮、右侧滑出抽屉（六项大写菜单 + 整页模糊 + 右缘滑入手势）、chat 走底部 ASK PIN AI 上拉（不在菜单）。
3. **Setting 支付页 dev 期全量复刻**（含 Stripe 管理）；上线 App Store 前按审核政策再改。
4. **球面迭代式逼近**：第一版 = 景深+漂浮的玻璃卡片云，随真机反馈逐轮调，最终目标「和网页的感觉一样」。
