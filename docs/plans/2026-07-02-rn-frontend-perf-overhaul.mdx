# RN 前端性能全面整改（apps/mobile）

> 状态：brainstorm 草稿（已定稿诊断，待实施）
> 日期：2026-07-02
> 适用：`apps/mobile`（Expo RN）+ 被其消费的 `packages/core`、`packages/state`
> 来源：Fable-5 八维度审计（73 条 confirmed-in-code 发现）+ Opus 对承重结论的独立复核

## 这份文档怎么读

- **执行者 = Opus 4.8**，逐条施工。每条改动都给了「改法 / 文件 / 验收」，不需要回到对话上下文。
- **验收环境 = 真机 iPhone**（yml，已删模拟器）。凡涉及视觉的改动，最终由 Mengli 在真机上像素级对齐现役 proactive-ai-frontend 后拍板。
- 完整原始发现（73 条，含 evidence/risk）已入库：`docs/plans/assets/2026-07-02-rn-perf-audit-findings.json`。
- 施工顺序见文末「推荐执行顺序」。**WS0 必须先做**——没有 Release 基线，后面所有测量都不准。

## 结论：这不是「缺缓存」，是「JS 线程被重活占住」

用户最初判断卡顿=缺本地数据库/缓存。审计推翻了大部分：缓存已经做得不错（TanStack Query + AsyncStorage 持久化 + keep-alive 页面栈 + 空闲预取）。真正的主因按影响排序：

1. **Debug build 放大器**：真机装的是 `-configuration Debug`（`build-rn-device.sh:71`），JS 跑未优化的 Hermes 字节码 + `__DEV__` 开着 = 全局 2–5× 慢。这是**所有症状的第一放大器**，必须先量 Release。
2. **AppShell 重渲级联**：`usePipeline`（4s/30s 轮询）等订阅住在 AppShell，屏幕都没 `React.memo`，每个轮询 tick 都把所有常驻屏 + 聊天栈重渲一遍。这是「点 tab 卡 / 页面渲染卡」的核心。
3. **首访同步挂载**：`navigate()` 在点击的同一个 commit 里同步搭 37KB 大屏，阻塞 JS 线程 → 「点了没反应」。
4. **isLoading 全屏 gate + persist 白名单太窄**：Profile/记忆/devices 没进缓存，冷启动首访转圈。这是用户「缺缓存」直觉命中的那 1/4。
5. **列表无虚拟化**：Ambient/Connect/Profile 的列表是 `ScrollView + .map`，一次性全渲染 → 滑动卡。

> RN 只有一根 JS 线程，无法加线程。行业做法 = worklet（UI 线程）/ native 分流 / 时间错峰。整改全程围绕「把重活从 JS 线程挪走」。

## ⚠️ 顺带发现一个安全问题（非性能，优先级独立拉高）

**Ambient 时间线 SQLite + live-transcript 内存 store 是 device-global，sign-out 从不清**（`WS8-SEC`）。A 账号登出、B 账号登入后，Ambient 页会显示 A 的时间线和转录历史 = **跨账号个人数据泄露**。这条**不要排进性能节奏，尽早单独修**（见 WS8-SEC）。

## 红线（施工不可违反）

1. **不换导航库**：手写 keep-alive 状态机是对的，不迁 React Navigation、不加 bottom-tab 库。
2. **不改 bundle id / team / scheme**：签名走 team `H83W52NS23`（liam 个人证书 OU）+ bundle `ai.pin.proactive.dev.mengli`。
3. **对话消息体禁入 TQ persister**：SQLite 才是消息体的本地真源，persister 只放 settings/cards/profile/memories/devices 这类小体量 server-state。
4. **`packages/*` 是共享层**：动 `packages/state`、`packages/core` 必跑 `npm run check:packages` + proactive-ai-frontend / apps/web 的 type-check + test（web 也消费同一份 hook）。
5. **视觉改动像素级对齐现役 proactive-ai-frontend**，真机由 Mengli 拍板。
6. **改动最小化、复用现有 pattern**（`usePageActive` 停帧、`useSinkDismiss` 的 gesture memo、KeepAlivePage 的 display:none 等都是现成范式）。

## WS0 — Release 基线（必须先做，只改配置）

**目标**：消除 Debug 放大器，后面每次测量都反映真实生产表现。

- **[CRIT] Release 真机 build 通道**

  - 文件：`.claude/skills/A-RN-frontend/scripts/build-rn-device.sh`、`apps/mobile/index.ts`
  - 验收：`CONFIG=Release bash build-rn-device.sh` 成功；`Release-iphoneos/PINAIDev.app/main.jsbundle` 存在；`lsof -ti:8081 | xargs kill` 杀掉 Metro 后 app 仍能冷启到 NOW 并流式聊天（证明 env 已 bake）。
- **[HIGH] 开启 Metro `inlineRequires`**
  - 改法：`metro.config.js` 在 `withNativeWind` 后加 `config.transformer.getTransformOptions = async () => ({ transform: { experimentalImportSupport: true, inlineRequires: true } })`；`npx expo start -c` 清缓存重启。让模块按首次使用求值，而不是启动时把整个模块图（7 屏 + 1713 图标 barrel + markdown/webview/skia）全 eval。
  - 文件：`apps/mobile/metro.config.js`
  - 验收：冷启时间在 Debug 和 Release 都明显下降（真机上百 ms 级）；冒烟：登录 / 7 个 tab / 聊天流式 / 切语言 / 前台推送 / ambient 都正常。
- **测量脚手架**：临时加一个 boot HUD（`performance.now()` 打点 App 首帧），做 Debug vs Release 的 A/B，把 S1–S4 还剩多少记下来，作为后续 workstream 的基线。整改收尾时移除。

**做完 WS0 先停下来让 Mengli 真机体验一轮**——很可能 S2/S4 直接可接受，S1 减半。据此再决定后面投入多少。

## WS1 — 干掉 AppShell 重渲级联（最高性价比，主治 S1/S2）

**目标**：让轮询/settings 写入不再把所有屏重渲一遍。这些改动互相依赖，**必须整组一起落**，否则单个 `React.memo` 是死代码。

- **[CRIT] 把订阅从 AppShell 抽进 `<ShellEffects/>`（null 渲染）**
  - 改法：新建 `ShellEffects.tsx`，原样搬入 `useAmbientConsentReconcile` / `useAmbientToggle` / `usePipeline` + shortcut ref 效应（AppShell.tsx:67-85）+ run-complete invalidation（:89-95）+ 1.2s prefetch（:100-128）。它 return null，挂在 `<CardActionsProvider>` 里当首个 child。AppShell 只留 view/visited/menu/chat/cardChat 状态 + `useComposio` + displayName。
  - 文件：`apps/mobile/src/components/app/ShellEffects.tsx`(new)、`AppShell.tsx`、`DebugPanel.tsx`(可选去重)
  - 验收：AppShell 顶加 `console.count('AppShell render')`；跑一次 generate，4s 轮询窗口内 AppShell 不再递增；改 Settings 也不递增；Siri shortcut generate + 跑完刷卡仍работает。
- **[HIGH] `useComposio` 用 `useMemo` 包返回对象**（`composio.ts:343` 每 render 新字面量 → 破所有下游 memo）
  - 改法：把整个 return 包进 `useMemo`，deps 列全 4 个 state + 16 个 useCallback（都已稳定）。保留 ConnectScreen 现有 destructure workaround（变冗余但无害）。
  - 文件：`packages/state/src/queries/composio.ts`；验收：`npm run check:packages` + web 端 type-check/test 绿；ConnectScreen 开关抽屉 render 计数持平。
- **[HIGH] `CardActionsProvider` 拆两个 context + memo**（`CardActionsProvider.tsx:39` 每 render 新 value → NOW/TASKS/CardDetailSheet 全重渲）
  - 改法：(1) AppShell 里 `onOpenChat` 用 `useCallback`；(2) `useCardActions` 把 `composio` 放 ref、从 `confirm` deps 去掉，让 confirm 稳定；(3) 拆 `CardActionsContext`（5 个 Set + 6 个 action，`useMemo` keyed on 11 identity）和单独 `ComposioContext`（只有 NOW 空态消费）。
  - 文件：`CardActionsProvider.tsx`、`useCardActions.ts`、`AppShell.tsx`、`NowScreen.tsx`
  - 验收：Tasks 可见 + 4s 轮询时，Row render 计数 0 增长；dismiss 一张卡两屏仍即时划线。
- **[HIGH] `React.memo` 7 个屏 + 稳定 AppShell 下发的所有 prop**
  - 改法：`headerProps` 用 `useMemo`；`navigate`/`openSettingPage`/所有屏回调用 `useCallback`（body 只 setState，deps 为 `[]` 或 `[navigate]`）；`handleDeleteAccount` → `useCallback([onSignOut])`；然后把 NowScreen/AmbientScreen/TasksScreen/ConnectScreen/ProfileScreen/SettingScreen + ChatSheet/CardChatScreen/DebugPanel/AgentRunIndicator 的默认导出包 `memo()`。`NowScreen.active` 保持普通 bool（球体停帧 gating 依赖它）。**顺序：先稳定 prop，再包 memo**。
  - 文件：`AppShell.tsx` + 上述各屏
  - 验收：各屏 body 加 `console.count`；开关抽屉 → 0 屏递增；开 ChatSheet → 只 NowScreen 递增；从 NOW 开 card chat → 只 NowScreen + CardChatScreen。
- **[MEDIUM] `memo(AppShell)`**：任何 settings 写入都会经 Root 把整树重渲；AppShell 从 Root 拿的 props（user/onSignOut）稳定，一个 memo 截断级联。文件：`AppShell.tsx`。
- **[MEDIUM] 修 `packages/state` 不稳定 callback deps**：`agent-runs.ts` refresh `[query]`→`[refetch]`；`user-settings.ts` patch `[patchMut]`→`[mutateAsync]`、refetch 同理（v5 里 refetch/mutateAsync 引用稳定）。文件：`agent-runs.ts`、`user-settings.ts`；验收 `check:packages` 绿。
- **[MEDIUM] `usePipeline` 用 select 投影**（P5 数据侧）：`agent-runs` 加 `useAgentRunsProjection(select)`，pipeline.ts 只 select `{id,kind,status,lastError}` 且 filter generator run——TQ 结构共享让「只有 progress/updatedAt 变」的 tick 产生同引用 → AppShell/DebugPanel 不重渲。文件：`agent-runs.ts`、`pipeline.ts`。
- **[LOW] `AgentRunIndicator`**：1s elapsed ticker 门控在「elapsed 真的可见」时才建 interval + `memo()` 包导出。文件：`AgentRunIndicator.tsx`。
- **[LOW] 可选**：从 `/agent-runs/active` 投影里砍掉没人读的 `updatedAt/progress/attempts`（`packages/core/agent-runs.ts`），恢复 TQ 结构共享；WS1 落地后再做的廉价打磨。

## WS2 — 导航延迟挂载（主治 S1「点了没反应」）

**目标**：点击立刻有反馈，首访大屏的挂载挪到手势之后。

- **[MEDIUM] `navigate()` 延迟切换 + 先关抽屉**
  - 改法：AppShell 的 `onNavigate` 先 `setMenuOpen(false)` 同步执行，再 `requestAnimationFrame(() => navigate(id))`（或 `InteractionManager.runAfterInteractions`）。keep-alive 保证重复访问零重挂，成本只在首访。
  - 文件：`AppShell.tsx`、`MenuDrawer.tsx`；验收：慢动作录屏，抽屉关闭 spring 无掉帧，新页 fade 完整 180ms。
- **[MEDIUM] `KeepAlivePage` 从 `onLayout` 起 fade**：首访 fade 用子树首次 layout 触发（而不是挂载 commit 同帧），保证 180ms 淡入不被昂贵 commit 吞掉。文件：`KeepAlivePage.tsx`。
- **[MEDIUM] 抽屉 overlay 首开后保留（display:none 不卸载）**：`mounted` 卸载改成 `shown=false` + `display:none`（同 KeepAlivePage 范式），2 次+ 开抽屉不再 mid-gesture 挂 2 个 BlurView。文件：`MenuDrawer.tsx`。（若 WS6 的 scrim blur flatten 先落，这条再评估。）

- **[HIGH] Ambient 时间线**（P4）：`timelineEntries` 用 `useMemo`；抽 `memo(TimelineRow)`（handleAmbientAction 走 ref-latest）；`ScrollView`→`FlatList`，hero/live/device strip 放 `ListHeaderComponent`。文件：`AmbientScreen.tsx`。验收：seed 100 条（`note='__mock__'`），初次只渲 initialNumToRender 行，滑动 ≥55 FPS。

## WS6 — 动画 / GPU 合成（主治 S2/S4 + 发热 + 包体）

- **[HIGH] 去 Skia：`AuroraBackground` 换 react-native-svg 或 baked 图**（同时砍 ~85MB native libs + 2 个常驻 GPU surface，画的是静态图）。推荐：6 个 SPOTS 用 `react-native-svg`（已是依赖）的 `RadialGradient` 1:1 复刻，或预烘焙成透明 WebP 叠在 `bg-gradient.jpg` 上；然后 `npm uninstall @shopify/react-native-skia` + prebuild。文件：`AuroraBackground.tsx`、`package.json`(、新 `aurora-spots.webp`)。→ 真机像素校验 + 待决问题。

## 推荐执行顺序（按性价比）

1. **WS0**（Release 基线）——先量，别盲改。**做完停下来让 Mengli 真机体验。**
2. **WS8-SEC**（跨账号 ambient 数据泄露）——安全独立优先，不排进性能节奏。
3. **WS1**（重渲级联）——最高性价比，直接治 S1/S2 卡顿。
4. **WS3**（SWR + 持久化）——治 S3 转圈，改动小。
5. **WS2**（导航延迟挂载）——治「点了没反应」。
6. **WS4**（列表虚拟化）——治 S4 滑动。
7. **WS6**（动画/GPU + 去 Skia）——治发热 + 部分 S2/S4 + 砍 85MB 包体。
8. **WS8**（其余泄漏 + 资源）——correctness + 内存。
9. **WS5**（渲染卫生）——打磨。
10. **WS7**（i18n/lucide 懒加载）——启动打磨。

每个 workstream 是独立可上线的 PR 组；WS1 内部要整组落。改 `packages/*` 的每条都跑 `npm run check:packages` + web 端 type-check/test。
