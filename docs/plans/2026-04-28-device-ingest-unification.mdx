# Device Ingest 统一设计

## 一句话

所有 device（手机 / omi 一类硬件 / 未来任何硬件）共用：
- **一张表**：`user_devices`（已有，扩 platform CHECK + 加可选 `model` 字段）
- **一个配对入口**：`POST /api/proactive/devices/register`（已有，复用）
- **一个 ingest 入口**：`POST /api/proactive/devices/ingest`（新建，吃掉旧的 `/api/mobile/items/ingest`；2026-04 已 retired——`/api/mobile/*` 路由 + 默认容器兜底全部移除，新接口强制 `X-Device-Id` + `X-Device-Token`）
- **一个落点**：`personal_signals`（必写）+ 选择性 fan-out 到 `raw.db.device_*_snapshot`（已有）+ 二进制走 FS

`ambient` 分支引入的 `media.db` ring buffer、`ambient.db` archive、`ambient_events` 表、WS ingest 全部砍掉。

## 不做什么

- 不加新表（除了 migration 改 `user_devices`）
- 不引入"connector manifest"抽象（device 类不需要，pull 类才需要）
- 不保留 ambient 分支的 WS 链路 —— HTTP multipart 够用，业务上不需要 200ms 级实时

## Schema 改动

### Migration 004：放宽 platform + 加 model

```sql
ALTER TABLE user_devices DROP CONSTRAINT IF EXISTS user_devices_platform_check;
ALTER TABLE user_devices ADD CONSTRAINT user_devices_platform_check
  CHECK (platform IN ('ios', 'android', 'web', 'wearable', 'sensor', 'embedded'));

ALTER TABLE user_devices ADD COLUMN IF NOT EXISTS model TEXT;
-- model 例子: 'iphone_15', 'pixel_8', 'omi_pendant_v1', 'friend_v2'
```

仅此而已。其它字段（display_name / metadata / token / paired_at = registered_at）已有。

## Ingest 接口形状

```
POST /api/proactive/devices/ingest
X-Device-Id: <uuid>
X-Device-Token: <plaintext token from registration>
Content-Type: application/json | multipart/form-data
```

### A) 纯结构化（手机 app inventory / 联系人 / 任何文本数据）

```json
{
  "items": [
    {
      "id": "uuid",
      "kind": "app_inventory_snapshot",
      "occurredAt": "2026-04-28T12:34:56Z",
      "title": "...", "summary": "...",
      "payload": { "apps": [...] },
      "salience": 0.4, "confidence": 0.9,
      "dedupeKey": "..."
    }
  ]

```

完全兼容现有 `MobileItemInput` 形状，旧 `/mobile/items/ingest` 改成 alias。

### B) 含二进制（图片 / 音频 / 视频 / 任何文件）

multipart/form-data：第一个 part 永远是 `meta` (JSON)，后面跟若干二进制 part：

```
--boundary
name="meta"; Content-Type: application/json

{ "items": [
    { "id":"...", "kind":"ambient.image_chunk",
      "occurredAt":"...", "binaryRef":"img-0",
      "mime":"image/jpeg",
      "payload": { "width":640, "height":480, "orientation":1 } },
    { "id":"...", "kind":"ambient.audio_chunk",
      "occurredAt":"...", "binaryRef":"aud-0",
      "mime":"audio/opus",
      "payload": { "duration_ms":5000, "sample_rate":16000, "codec_id":21 } }
] }

--boundary
name="img-0"; Content-Type: image/jpeg
<JPEG bytes>

--boundary
name="aud-0"; Content-Type: audio/opus
<Opus bytes>
--boundary--
```

## 后端写入逻辑

```ts
async function handleDeviceIngest(deviceId, items, binaries) {
  for (const item of items) {
    let filePath: string | null = null;

    if (item.binaryRef) {
      const bin = binaries[item.binaryRef];
      filePath = await writeMediaFile(deviceId, item, bin);
      // /app/data/media/<device_id>/<YYYY-MM-DD>/<uuid>.<ext>
    }

    // 1) 必写：personal_signals
    await ingestPersonalSignals([{
      ...toSignal(item, deviceId),
      payload: { ...item.payload, file_path: filePath },
    }]);

    // 2) 选择性：raw.db.device_*_snapshot（沿用现有）
    fanoutToRaw(item, deviceId);
  }
}
```

## 高频 chunk 写入的聚合策略

omi 一秒级图音频流如果逐 chunk 写 `personal_signals`，signal 表会膨胀。两种缓解：

1. **端侧聚合**（首选）：手机 BLE 收到 200ms 音频后，本地 buffer 5-10s 一批，HTTP 一次推。后端按聚合后的 chunk 写 1 行 signal。
2. **后端 rollup**：逐 chunk 仍然落文件，但 signal 按"分钟"或"事件"粒度聚合写入。kind = `device.media_window`，payload 引用这一段所有 file_path。

ambient `event-generator` 保留：定时跑 → STT + VLM → 写 `kind='ambient.event'` 的 signal（payload 含 transcript / summary / image_ids list）。这是"高价值事件"，写 signal 完全合理。

## 取最新一帧（替代 `pin media get-latest-frame`）

```sql
SELECT payload FROM personal_signals
WHERE source = 'device' AND device_id = ?
  AND kind = 'ambient.image_chunk'
ORDER BY occurred_at DESC LIMIT 1;
```

→ 拿到 `payload.file_path` → 读文件返回。15s stale 阈值仍然在 CLI 工具层判。

## 横向扩展验证

加新硬件需要做的：
1. 用户配对 UI（如果是 BLE，复用 `useBleDevice.ts`；如果是 USB / WiFi，自己写）
2. `POST /api/proactive/devices/register` 注册（platform=wearable/sensor/...，model='xxx'）
3. APP 端把数据塞进 `/devices/ingest`，定 `kind` 字段决定语义
4. 容器端：如果 `kind` 是已有的（ambient.image_chunk / app_inventory_snapshot 等）零代码；如果是新 kind，加一行 fan-out（可选）

完全不碰 personal_signals / raw.db schema。
