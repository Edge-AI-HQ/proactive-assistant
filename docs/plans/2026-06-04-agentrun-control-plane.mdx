# Agent Core:统一 agent 执行内核

> **状态**:实施计划(第四版,已纳入两路对抗 review 的全部 P0/P1 + 用户 4 项拍板,可开工)。彻底重构,**不考虑 backward 兼容**。
>
> **一句话**:7 个 agent(main_chat / card_execution / proactive / generator / dream / evolve / crystallize)各有一条手写执行链路。Agent Core 统一成 **actor 模型**:会话=actor(`Session`),mailbox(`Message` 队列),per-session 串行,一次 `Run` 醒来合并消费 mailbox、跑一轮,输出经 `FrameBus` live streaming。**控制平面在 web(账本/worker/bus,碰 DB),执行在 chat(LLM loop,不碰 DB),协议在 shared**——与现有 web/chat 信任边界重合。
>
> **定位**:[2026-06-01](./2026-06-01-agent-architecture-redesign) §8 四层 + [2026-06-02](./2026-06-02-agent-directory-and-tool-paradigm) 目录解决"单 agent 怎么组织代码";本文解决"跨 agent 怎么统一编排执行"。执行器=06-01 的 `harness/`;`RunProfile`(web)与 `AgentSpec`(chat)互补。
>
> **对标**:**actor 模型**(Erlang/Akka mailbox、Cloudflare Durable Objects)、**Claude Managed Agents**(stop_reason 挂起态 / events / multiagent threads)、**LangGraph Platform**(Runs / `multitask_strategy` / `interrupt`+`Command(resume)`)、**Claude Code** `Task.ts`、**Temporal/Restate**(durable + per-key 串行)。
>
> **明确不碰**:① checkpoint/context 增长(06-01 §8.2 + 独立 PR);② trust boundary(web 持凭据+DB、chat 不碰 DB、JWT、ruff banned-api 全不变)。
>
> **第四版相对第三版的关键修正**(两路对抗 review 后):frames 不落库改 **FrameBus(内存/Redis)live streaming**(去 frames 表,4→3 表);重连不回放改 **waiting 模式**(Claude app 做法);message **role 统一 user + 加 source 维度**;**HITL 用 langgraph/deepagents 原生**(awaiting_input 不再是空壳);worker **notify + 轮询兜底**(丢通知不卡死);cancel **真停 chat+sandbox**;lease **fencing**;加廉价口子(`multitask`/`parent_run_id`/`idempotency_key`/`notify_run_status`)。

## 一、TL;DR

```
一个 Session(=actor,= langgraph thread_id = 串行锁 key)
  ├─ Mailbox:任何来源输入都是一条 Message(role 统一 user;source 区分 user/heartbeat/...)
  ├─ per-session 串行:同一 Session 一次只跑一个 Run(lease,per-drain)
  ├─ Run:醒来 → 合并消费 mailbox 全部 pending Message(多条 HumanMessage 一并发)→ 跑一轮
  ├─ Frame:输出经 FrameBus(内存/Redis pub/sub)live 推送,不持久化
  └─ HITL:副作用工具用 deepagents interrupt_on → langgraph interrupt() → run 进 awaiting_input
           → 决策走 mailbox 一条 message → Command(resume) 同 thread 续跑
```

**三平面**(落在信任边界):
- **控制平面 = web**(`web/agent_core/`):3 表账本、Service、Worker、FrameBus、ChatRunClient、RunProfile。
- **执行平面 = chat**(`chat/transport/routes/run.py` + `agents/`):stateless executor,按 `AgentKind` 选工厂,跑 `astream_events`,产帧 + 翻译 `__interrupt__`。
- **协议 = shared**(`shared/agent_run.py`):`AgentKind` 枚举、Frame 信封、run-JWT claim、resume 协议。

**重连/刷新交互(Claude app 模式)**:live streaming 只给当前连接;断连重连查 run 状态——`running` 显示 "agent 正在处理…"(不回放 in-flight 帧)→ 终态读 `pai_chat_messages` 显示最终结果。

## 二、为什么 actor 模型(统一了什么)

| actor 概念 | 现在散落在 | 统一后 |
|---|---|---|
| actor 实例 | proactive `(user,thread)` lease / chat-stream session_key / scheduler task | **`Session`**(`pai_agent_sessions`) |
| mailbox | proactive_inbox / chat-stream 同步直发 / scheduled_task payload | **`Message`**(`pai_agent_messages`) |
| 串行消费 | proactive per-thread lease / scheduler per-fire lease | **per-session lease(per-drain)** |
| 一次执行 | proactive turn / scheduled_task_run / 一次 stream_chat | **`Run`**(`pai_agent_runs`) |
| 输出 | proactive bus 帧 / chat-stream 同请求 SSE / generator 结构化返回 | **`Frame`**(FrameBus live,不持久) |

价值:加一个新 agent = 注册一条 `RunProfile` + 写一个 agent 工厂,内核零改动。

**三个吸收的决定**:① 输出统一 streaming(后台=无订阅者的流,结构化结果从终态提取存 `run.result`);② **心跳也是 message**(`role=user`、`source=heartbeat`,系统代发);③ **mailbox merge**(一次消费全部 pending,多条 HumanMessage 一并发;矛盾指令交模型化解)。

## 四、actor 核心机制

### 4.1 Session = 串行锁 key
`session_id` = langgraph `thread_id` = lease key = mailbox 归属。main `main-<uid>-<rand>` / card `card-thread-<card_id>` / proactive `proactive-<uid>`。batch(generator/dream/...)无持续 Session,one-shot Run。

### 4.2 per-session 串行(per-drain lease,应用层锁)
langgraph `thread_id` 只给状态隔离,不给并发串行;同 thread 并发 Run = checkpoint 竞态。lease 由内核实现(泛化 proactive 075 的 per-thread lease)。**lease 是 per-drain**(worker 每次醒 acquire→drain→release),不是 per-run 长期持有;run 的挂起态(awaiting_input)存 DB,不靠占锁。

### 4.3 mailbox merge(多条 message 一并发)
Run 醒来 `claim_pending` 取该 session 全部未消费 Message,作为多条 HumanMessage 一次喂 agent。本轮跑时新到的 message 下一圈合并。
- **role 统一 user**(给 LLM);**source 维度**(`user|heartbeat|cron|system_event|card_bootstrap|tool_decision`,给 worker 做记账/调度,不给 LLM)。
- **proactive 记账靠 source 集合**:消费的 message 任一 `source=user` → 用户发起的 turn,不记 silent;全 `source=heartbeat` 且无 notify_user → 记 silent(写 proactive_events 卫星)。
- **心跳窗口 worker drain 时现算**:heartbeat message enqueue 时只是标记,worker 消费时才查 timeline 窗口拼成 agent 输入(保留现状 `_execute_turn` 窗口逻辑,避免快照过期)。
- ⚠️ **连续 user message 是硬依赖,CORE-1/2 最早实测**(见 §十三)。

### 4.4 统一 streaming via FrameBus(不持久化)+ 重连 waiting
- **FrameBus 抽象**:`publish(session_id, frame)` / `subscribe(session_id) -> AsyncIterator[frame]`。实现:**内存**(dev 单实例,进程内 asyncio fan-out)/ **Redis pub/sub**(prod 多实例)。worker relay chat 的帧 → FrameBus.publish。**不落任何表**(配合重连 waiting,不需要持久 replay)。
- **三层退两层**:live(FrameBus,瞬时)+ 历史真源(`pai_chat_messages`,`ChatTurnRecorder` 写,终态)。**无 frames 表 / 无 cursor / 无 TTL sweep**。
- **重连/刷新(Claude app 模式)**:前端断连重连 → 查 run 状态:`running` → 显示 "agent 正在处理…"(订阅 FrameBus 收后续,但**不回放**已发帧)+ 监听 `notify_run_status`;终态 → 读 `pai_chat_messages` 显示最终结果。半截 in-flight 帧丢失可接受(history 兜底)。
- ⚠️ **硬提醒**:内存 FrameBus **只在单 web 实例成立**。prod `min_machines_running=2`,**上线前必须切 Redis**(否则 subscribe 实例 ≠ 跑 run 实例时收不到 live 帧)。FrameBus 接口稳定,切实现一处改动。

## 五、HITL / 工具审批(langgraph + deepagents 原生)

不自己造,用三家一致的框架原生做法。

**链路**:
1. **chat 配置**:副作用工具用 `create_deep_agent(interrupt_on={"GMAIL_SEND_DRAFT": True, ...})` → `HumanInTheLoopMiddleware` 在工具调用前抛 langgraph `interrupt()`。
2. **chat 翻译**(CORE-4 ✅ 实测落地):langgraph `interrupt()` 在 `astream_events(v2)` 以 `on_chain_stream` 的 chunk `{"__interrupt__": (Interrupt(value={action_requests, review_configs}, id),)}` 出现。`langgraph_to_sse` 翻译成 `requires_action` 帧(interruptId + toolName + args + argsPreview + allowedDecisions)。
   - **推翻 06-01**:06-01 §5.4 以为「interrupt 帧在 SSE 被丢、不可翻译」,真因是旧 `langgraph_to_sse` 根本没处理 `on_chain_stream`。CORE-4 真实测:interrupt **可捕获**、`Command(resume={"decisions":[…]})` **能同 thread 重入**(approve→工具执行 / reject→跳过)。`propose_action` 软闸可在 RC 退役。
3. **web 挂起**:worker 收到 `requires_action` 帧 → `run.status='awaiting_input'` + `pending_action JSONB`(等待的 tool_use_id + 摘要)+ `notify_run_status`(前端弹审批 UI)。**释放 lease**(per-drain),不长期占锁。
4. **决策回灌走同一 mailbox**:用户批准/拒绝 = 一条 Message(`role=user`、`source=tool_decision`、`meta={tool_use_id, decision: allow|deny, message?}`)。
5. **resume**:worker drain 时检查——session 有 `awaiting_input` run + 来了匹配的 decision message → 调 chat `/agent/run` 的 **resume 模式**(`{session_id, resume:{tool_use_id, decision}}`)→ chat 用 **同 thread_id + `Command(resume=decision)`** 续跑。
   - session 有 awaiting_input run + 非 decision message → 排队等(保持串行,审批期间不起新 run);无 → 正常 create。

**对齐三家**:Managed Agents(`stop_reason=requires_action` + `user.tool_confirmation` 走同 events 流)/ LangGraph(`interrupt()`+`Command(resume)` 同 thread)/ OpenAI(`requires_action`+`submit_tool_outputs`)——挂起态 + 判别字段 + 带 tool_use_id 的决策回灌 + 同会话 resume。

## 六、数据流(穿越边界,含 HITL)

```
前端 POST /api/agent/send
  → web post_message → MailboxRepository.enqueue(DB,含 idempotency_key 去重)→ bus.notify_message
  → web Worker(notify 醒 / interval 轮询兜底)→ SessionRepository.acquire_lease(DB)
      → 检查 session 有无 awaiting_input run:
          有 + decision message → resume 分支(下方)
          无 → MailboxRepository.claim_pending 多条(DB)→ RunRepository.create(DB)
      → ChatRunClient 签 run-JWT → POST chat /agent/run {kind, session_id, messages}
          → chat make_<kind>_agent → astream_events → 帧流(含可能的 __interrupt__)
  → web Worker relay 每帧:FrameBus.publish(live)+ ChatTurnRecorder.feed(攒 history)
       + 周期 refresh_lease(fencing,防 run 超 TTL 双 writer)
  → 收到 requires_action 帧 → run.status=awaiting_input + pending_action + notify_run_status + 释放 lease
  → 否则终态:RunRepository.complete(result=终态提取)+ ChatTurnRecorder.flush→pai_chat_messages
       + MailboxRepository.mark_consumed + notify_run_status
HITL resume:
  前端 POST /api/agent/decision → mailbox.enqueue(source=tool_decision)→ notify
  → Worker → acquire_lease → 见 awaiting_input run + decision → ChatRunClient resume 模式
  → chat Command(resume=decision) 同 thread 续 → 帧流继续 → 终态
前端 GET /api/agent/stream(断连重连)
  → 查 run 状态:running→显示 waiting + 订阅 FrameBus 后续 + 听 notify_run_status;终态→读 pai_chat_messages
```

```sql
pai_agent_sessions (
  session_id   TEXT PRIMARY KEY,
  user_id      BIGINT NOT NULL,

pai_agent_messages (                                   -- mailbox

  session_id      TEXT NOT NULL,

  session_id    TEXT,                                  -- 会话型有;batch one-shot NULL
  user_id       BIGINT NOT NULL,
  agent_kind    TEXT NOT NULL,

```

## 十、Worker drain loop

```
被 bus 唤醒 或 interval 轮询(兜底,防丢通知)→ 找有 pending message 或 awaiting_input+decision 的 session:
  acquire_lease(session_id)   # per-drain;抢不到=别人在跑
   won:
     # 1) HITL resume 优先
     if 有 awaiting_input run:
        if mailbox 有匹配 decision message → ChatRunClient.resume(run, decision);处理帧(同下)
        elif mailbox 有非 decision message → release;return   # 审批期间不起新 run,保持串行
        else → release;return
     # 2) 正常 run
     while True:
       refresh_lease
       msgs = mailbox.claim_pending(session_id)        # 多条
       if not msgs: release_lease_if_empty; break
       run = runs.create(session_id, kind, trigger=高优先级 source)
       async for frame in ChatRunClient.run(kind, session_id, msgs):
           FrameBus.publish(session_id, frame); recorder.feed(frame)
           周期 refresh_lease                          # fencing:防 run 超 TTL 双 writer
           if frame == requires_action:
               runs.set_awaiting(run, pending_action); notify_run_status; release; return
       runs.complete(run, result=extract); recorder.flush→pai_chat_messages
       mailbox.mark_consumed(msgs, run); notify_run_status
       # proactive 记账:msgs 全 heartbeat 且无 notify_user → 记 silent(卫星)
reaper(interval):running 超时无 lease 的 run → fail(防僵尸行)
```

## 十一、关键不变量

- **chat 永不碰 DB**:只产帧;FrameBus/chat_messages 落地由 web 写。
- **凭据只在 web**;前端只跟 web 说话;ruff banned-api 仍禁 web↔chat 互 import,共享走 `shared/agent_run.py`;不引第三进程(worker 在 web lifespan)。
- **cancel 真停**:web abort 对 chat 的 HTTP;chat `/agent/run` 必须处理 client disconnect → abort LLM + **释放 Daytona sandbox**(否则 UI 停了但算力/计费没停,参考 MEMORY "main chat sandbox hang")。cancel 丢弃 partial;interrupt 保留 partial。
- **single-writer 靠 fencing 不靠 TTL**:relay 循环周期 `refresh_lease`;写操作带 `lease_owner` WHERE,过期 owner 写不进。
- **副作用幂等**:chat stateless + web relay = at-least-once,崩溃重放;side-effect tool 带 idempotency key(接 Composio allowlist)。
- **worker 正确性靠轮询,不靠通知**:notify 只是低延迟优化,丢了 interval 兜底。

## 十七、RC-1 实施计划(proactive 切 actor)

**用户决策**:merge 时 user + heartbeat 都 `role=user`、按 FIFO 顺序一并发给 agent(source 仅用于 worker 记账/路由);做**完整 RC-1 后端**;前端 `ui/proactive` 只改内部调用链走 service,UI 不动(RC-5)。

**proactive 特有、必须挂到 kernel 的 2 点**(2026-06-05 用户简化方案:心跳在 enqueue 时拼,不在 worker drain 现算):
1. **heartbeat content 在 scheduler enqueue 时拼**:scheduler tick 用游标(`last_tick_at`→now)查 timeline → 拼好 content → `post_message(source=heartbeat, content=窗口文本, meta={windowStart,windowEnd})` + advance 游标。worker drain **完全通用**(content 已拼,当普通 `role=user` message 发,不区分),只加两个轻钩子:drain 时按 source=heartbeat publish `tick_frame` 给前端、终态记 silent。**权衡**:enqueue 时快照固定——agent 忙时心跳在 queue 等,drain 时 content 已 stale(下个心跳补,proactive 非实时可接受);**游标(不是死的"过去 n 分钟")保证不漏/不重**。
2. **silent-by-default 靠 prompt,不再用 input_kind**:proactive agent prompt 总原则 = 默认沉默 + 有 user 消息就回答;**silent 记账按 source 集合**——消费的 msgs 全 `heartbeat` 且无 `notify_user` → `record_event(silent)`;任一 `user` → 不记。

**步骤(每步本地端到端验证):**
| 步 | 做什么 | 验证 |
|---|---|---|
| RC1-a | ✅ `web/services/proactive_window.py`:`build_heartbeat_message`(游标→now 拼窗口,返回 HeartbeatWindow)+`advance_cursor`+`tick_frame` | 单元 |
| RC1-b | scheduler `proactive.tick` handler→`build_heartbeat_message`+`post_message(heartbeat,content,meta)`+`advance_cursor` | post tick→queue 里有拼好的心跳 |
| RC1-c | `AgentRunWorker` 两个轻钩子:drain heartbeat→publish `tick_frame`(从 meta);终态全 heartbeat 无 notify_user→`record_event(silent)`。drain 主体通用 | 端到端 heartbeat turn |
| RC1-d | enqueue 改 service:`ui/proactive /send`→`post_message(source=user)` | post user→drain |
| RC1-e | chat proactive 按 kind 接 messages:`ChatRunClient` kind=proactive 路由;chat 入口按 kind 选 `make_proactive_agent` + 接 `messages`;prompt 去 input_kind | proactive agent 真跑 |
| RC1-f | `ui/proactive /stream`→`service.subscribe`、`/cancel`→`service.cancel`;`ProactiveRepository` 瘦身(删 lease/inbox-drain,留 `record_event`+cursor);删 proactive_loop drain/lease + `proactive_bus` | 前端透明 |
| RC1-g | 端到端:真实 heartbeat turn(窗口+silent)+ user 消息 + cancel + 多 tick | 全栈 |

**风险**:① 多 heartbeat 合并成一个窗口(非每 tick 一个)② `notify_user` 检测(relay 帧看 `chat:tool:start` name=notify_user)③ cursor 在终态推进 ④ timeline 现算只能 web(信任边界)⑤ proactive prompt 去 input_kind 后行为回归。
